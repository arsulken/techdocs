# Система публикации технической документации

Автор работы: **Васильев Арсений Витальевич**.

Репозиторий: https://github.com/arsulken/techdocs

Встроенная документация включает установку в Windows, руководство читателя, архитектуру и модель данных, решение типичных проблем, резервное копирование, быстрый старт и регламент публикации. Все статьи доступны сразу после `seed_demo`; их исходный текст хранится в `docs/knowledge.json` и в команде заполнения данных.

Основание: тема со скриншота и практические шаги на странице 74 файла «ЛК1_Фреймворки_Введение.pdf». Приложенный файл является вводной лекцией; отдельного задания с номером, критериями оценивания и требованиями к оформлению в нём нет. Реализован учебный Django-проект по перечисленным в лекции шагам.

## Запуск в Windows

1. Распакуйте архив и откройте папку `techdocs`.
2. Дважды щёлкните `START.cmd`. При первом запуске нужен интернет для установки зависимостей. Скрипт использует установленный Python либо Python из среды Codex и создаёт отдельное окружение `.venv`.
3. Дождитесь запуска сервера и откройте http://127.0.0.1:8000/ . Окно запуска должно оставаться открытым. Для остановки нажмите Ctrl+C.
4. Для доступа к админ-панели на новой копии проекта создайте пользователя в другом терминале:

```powershell
.\.venv\Scripts\python.exe manage.py createsuperuser
```

Админ-панель: http://127.0.0.1:8000/admin/ . Для уже подготовленной локальной копии данные входа сохранены отдельно в `../Доступ.txt`; этот файл не включается в архив исходников.

Если порт 8000 занят работающей копией, используйте её либо запустите другую на 8001:

```powershell
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8001
```

## Ручная установка

Скачать проект через Git:

```powershell
git clone https://github.com/arsulken/techdocs.git
cd techdocs
```

Основная ветка: `main`. Метка `v3.0` соответствует ступени «Веб-приложение (Django)» из лестницы версий на странице 68 лекции. История коммитов сохраняет первоначальный вариант и добавление документации с тёмной темой. Имена ветки и репозитория выбраны для проекта: лекция не задаёт их явно.

Проверено на Python 3.12.14 и Django 5.2.17. Python 3.10+ совместим с выбранной веткой Django. Использована ветка [Django 5.2 LTS](https://docs.djangoproject.com/en/5.2/releases/5.2/). Зависимости зафиксированы в `requirements.txt`.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_demo
.\.venv\Scripts\python.exe manage.py createsuperuser
.\.venv\Scripts\python.exe manage.py runserver
```

## Возможности

- Каталог проектов и поиск документов по названию и описанию внутри проекта.
- Чтение последней опубликованной версии и просмотр истории публикаций.
- Управление четырьмя сущностями через стандартные формы Django Admin.
- Черновики не видны в публичном каталоге, в истории и по прямым адресам.
- Дата публикации устанавливается автоматически; опубликованные версии нельзя редактировать через приложение. Для исправления создаётся новая версия.
- Номер версии уникален внутри документа, адрес документа уникален внутри проекта.
- Ссылочная целостность защищена `PROTECT`; удаление версий через админ-панель запрещено.
- Текст экранируется шаблонизатором; административные POST-запросы защищены CSRF.

## Модель данных

```text
Project (проект) 1 ─── N Document (документ)
Document         1 ─── N Version (версия)
Author (автор)   1 ─── N Version
```

Автор связан с конкретной версией: один документ может в разные моменты редактироваться разными авторами. Сущность `Author` описывает авторство и не является учётной записью входа. Вход редактора обеспечивает стандартная модель пользователей Django. Последняя версия определяется датой публикации и первичным ключом при равных датах, а не строковым сравнением номеров.

## Сценарий защиты

1. Открыть каталог: два проекта, восемь опубликованных документов, девять публикаций и два автора.
2. В проекте «Платформа ТехДок» найти «Регламент публикации».
3. Открыть «Быстрый старт»: по умолчанию версия 1.1; перейти к 1.0 через историю.
4. Войти в админ-панель. Показать четыре сущности и черновик 1.2.
5. Открыть черновик, изменить текст и установить «Опубликована». Сохранить.
6. Обновить публичный документ: теперь открывается 1.2, а предыдущие версии остаются в истории.
7. Запустить тесты и объяснить связи моделей и архитектуру MVT.

`seed_demo` создаёт отсутствующие записи, не дублирует их и не сбрасывает изменения. После публикации демонстрационного черновика повторный вызов команды не вернёт его в черновики.

## Границы работы

Это локальное учебное приложение с SQLite и dev-сервером. Редактирование выполняется в Django Admin; отдельного кабинета редактора, REST API, Docker и CI/CD нет: в лекции это последующие этапы. Неизменяемость публикаций обеспечивается моделью и админ-панелью, а не защитой от прямого SQL или ORM `update()`. Для размещения в интернете понадобятся отдельные производственные настройки, секретный ключ, HTTPS и сервер приложений. Названия учебного заведения, группы и преподавателя не добавлялись, поскольку не были предоставлены.
